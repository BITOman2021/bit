# سير عمل موقع ثلاثي الأبعاد (4 مراحل)

**القاعدة الذهبية:** خطوة واحدة في كل طلب، راجع النتيجة قبل التالي، ولا تنشر شيئًا قبل قرار صريح من المستخدم.

| # | المرحلة | المهارة |
|---|---------|---------|
| 01 | حدّد الفكرة (الهدف، الجمهور، المحتوى، الناقص) | `web3d-brief` |
| 02 | خطّط الموقع (قراءة فقط ثم خطة ملفات) | `web3d-brief` (القسم: بداية بطلب قراءة) |
| 03 | ابنِ وجرّب على مراحل | `web3d-phased-build` ← `web3d-effect-planner` ← `web3d-facts-guard` |
| 04 | راجع بأمان | `web3d-fix-issue` ← `web3d-review-checklist` ← `web3d-prelaunch-review` |

## قواعد عامة
- ابدأ بمجلد مستقل ولا تعدّل ملفات قديمة قبل قراءتها وشرحها؛ خذ نسخة احتياطية (git) قبل التعديلات الكبيرة.
- لا تنشر، لا تشترِ، لا تحذف، لا تغيّر إعدادات حسابات.
- لا تخترع أسعارًا أو شهادات أو عملاء أو نتائج. الناقص يُعلَّم «بحاجة تأكيد».
- ثبّت المحتوى والتنقل أولًا، ثم أضف 3D كطبقة واحدة مع بديل ثابت.
- في النهاية: اذكر ما فحصته فعليًا وما لم تفحصه، وأسماء الملفات المتغيرة.
- تنبيه: واجهة Codex وميزاته تتغير؛ ارجع للتوثيق الرسمي قبل أي خطوات تقنية محددة.
